Service Performance Reporting

Turn a fictional request dataset into a focused report of latency, errors, traffic, and endpoint behavior.

The problem

A dashboard becomes misleading when its charts silently use different populations or time windows.

The implementation choice

Calculate every card and endpoint row from the same filtered record set, with metric definitions visible.

The browser groups generated request records and computes aggregates. No backend, API key, or external chart service is required.

What you can verify

  • Web and mobile filters
  • Selectable time windows
  • Nearest-rank P90 latency
  • Endpoint breakdown and CSV export

Compare web and mobile requests over one hour and six hours. Identify the endpoint contributing the most server errors.

Scope and limits

No OpenSearch or production logs are queried. Every value comes from generated records. Percentiles use the nearest-rank definition, and all records have an HTTP status.

This public edition demonstrates engineering concepts. It makes no claim about measured client impact or production readiness.
