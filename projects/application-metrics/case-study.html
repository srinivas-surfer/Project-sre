Application Metrics Explorer

Compare fictional service measurements over time and see how an alert threshold changes the interpretation.

The problem

A last-value card alone can hide a growing trend or a brief spike. Different measurement types also require different aggregation rules.

The implementation choice

Show the chart, last value, peak, and a clearly defined window average together; use request-weighted error rates.

A local dataset contains gauge samples and per-interval request/error counts. Browser functions compute derived rates and chart values.

What you can verify

  • Three fictional services
  • CPU, memory, and error-rate views
  • Adjustable threshold
  • Sample table and CSV export

Compare the worker and API services. Adjust the CPU threshold and inspect the count of samples above it.

Scope and limits

The browser uses deterministic synthetic interval measurements. CPU and memory are gauge samples; error rate is errors divided by requests. This is not a live collector or a capacity recommendation.

This public edition demonstrates engineering concepts. It makes no claim about measured client impact or production readiness.
